EASYFFMPEG — BACKEND CHANGES
==============================

FILE CHANGED: src-tauri/src/lib.rs
------------------------------------

WHAT WAS THERE BEFORE:
  - greet()           — a hello-world demo command, unused
  - convert_filetype() — called ffmpeg and blocked until it finished,
                         no progress info, no cancel, and was
                         registered twice in invoke_handler (bug:
                         only the second one actually worked)

WHAT WAS ADDED / CHANGED:

1. probe_file(path)
   WHY: Before converting, the frontend calls this to find out how
        long the file is (in seconds). We need that number so we can
        work out "FFmpeg is 30 seconds in out of 120 seconds = 25%".
   HOW: Runs `ffprobe -show_entries format=duration` and returns the
        number it prints.

2. convert_file(id, input, output, duration, options)
   WHY: The old convert_filetype() blocked completely — the app
        froze until FFmpeg finished with no way to show progress or
        cancel. This replaces it.
   HOW: Spawns FFmpeg with `-progress -` which makes FFmpeg print
        machine-readable progress lines to stdout (like
        "out_time_us=4000000"). We read those lines one by one,
        calculate the percentage, and send it to the frontend as a
        "conversion-progress" event. The frontend listens for that
        event and moves the progress bar.
        Stderr is read on a separate thread so its internal buffer
        never fills up (which would silently freeze FFmpeg).
        The options struct lets the frontend pass in quality, codec,
        resolution scale, and trim times — all optional.

3. cancel_conversion(id)
   WHY: Users need to be able to stop a conversion in progress.
   HOW: When a job starts, its OS process ID (PID) is saved in a
        shared HashMap (JobStore). cancel_conversion looks up that
        PID and kills the process with taskkill (Windows) or kill -9
        (Mac/Linux). FFmpeg dies, its stdout closes, the progress
        reading loop ends, and convert_file returns an error — which
        the frontend shows as a cancelled state.

4. reveal_in_folder(path)
   WHY: After conversion, the "Reveal in Finder" button needs to
        open the folder where the output file lives.
   HOW: Gets the parent directory of the output path and opens it
        with explorer (Windows), open (macOS), or xdg-open (Linux).

5. Bug fix: double invoke_handler!
   WHY: The old code called .invoke_handler() twice. In Tauri v2
        the second call silently replaces the first, so `greet` was
        never actually reachable. All four commands are now
        registered in a single invoke_handler! call.

6. JobStore state
   WHY: To make cancellation work, we need to store the PID of each
        running FFmpeg process somewhere that both convert_file and
        cancel_conversion can access.
   HOW: A HashMap<String, u32> (job id -> PID) wrapped in a Mutex
        so it's safe to use from multiple commands at once. Registered
        with .manage() so Tauri injects it into commands automatically.


FILE CHANGED: src-tauri/tauri.conf.json
-----------------------------------------
  - Window title changed from "easyffmpeg" to "EasyFFmpeg"
  - Window size changed from 800x600 to 960x660 (matches the UI design)
  - Added minWidth/minHeight so the window can't be shrunk too small


FILES REPLACED: src/App.tsx, src/App.css
------------------------------------------
  The prototype UI (raw HTML with tabs and text fields) was replaced
  with a full React UI that connects to the new Rust commands above.
  The CSS implements the design token system (orange accent, dark
  surfaces, 8px spacing scale).

  What is wired up:
  - Drag-and-drop via Tauri's onDragDropEvent (gives real file paths)
  - "Add Files" button uses the existing dialog plugin
  - Dropping a file calls probe_file to get duration
  - Convert button calls convert_file for each queued file
  - Progress bar moves in real time from "conversion-progress" events
  - "Reveal in Finder" calls reveal_in_folder
  - "Cancel" calls cancel_conversion
  - "Retry" resets the item to queued state


WHAT STILL REQUIRES FFMPEG ON THE SYSTEM:
------------------------------------------
  The app calls `ffmpeg` and `ffprobe` by name. They must be installed
  and available on the user's PATH. On Windows this typically means
  adding the FFmpeg bin folder to Environment Variables > Path.
  Bundling FFmpeg inside the app installer is a future step.
